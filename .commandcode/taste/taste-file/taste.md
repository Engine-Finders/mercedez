# Taste File
- **URL and canonical must be identical for all pages.** The canonical tag must match the page's actual URL exactly — no mismatches tolerated. Confidence: 0.9
- **Pragmatic over dogmatic — dynamic or hardcoded, whichever is faster to ship.** When given a choice between a dynamic solution and hardcoding, pick the one that gets the job done quickest. Confidence: 0.8
- **Registry files are the source of truth for slugs and routes.** All URL generation (sitemaps, canonicals, navigation) must derive from registry JSON files (`src/data/registery/*/pages.json`), never from raw filesystem file names. Confidence: 0.8
- **Verifies builds after code changes.** After any changes to page-generation logic (sitemap, metadata, routing), runs a full build to confirm no breakage. Confidence: 0.7
- **Defensive `dangerouslySetInnerHTML` with `|| ""` fallbacks.** When rendering HTML strings from JSON data, every `__html` value is guarded with a fallback to empty string (e.g., `row.field || ""`) — never passes `undefined` or `null` to `dangerouslySetInnerHTML`, which crashes React. Confidence: 0.7
- **Prefers component-level backward compatibility over bulk data migration.** When field names differ across data files (e.g., some JSONs use `avgReconCost`, others `avgRebuildCost`), the consuming component handles both conventions (`newField || oldField || ""`) rather than bulk-editing all data files to match. Faster, safer, less churn. Confidence: 0.7
- **Static/repeated content goes in components, dynamic content stays in data.** Content that is identical across all dynamic pages (e.g., section H1/H2 headings) gets hardcoded directly in components rather than duplicated in every JSON, and is tracked in a plaintext reference inventory file (e.g., `all-headings.txt`) organized by page type for later use. Confidence: 0.7
- **Wants an explicit list of what was fixed after debugging.** After investigating and fixing a bug, the user expects a concise bulleted summary of the root cause and each change made, not just a "fixed it". Confidence: 0.6
- **Handles testing/build himself; agent should focus on the edits.** When delegating a code change, the user will run the tests/build himself ("i will do the rest the testing build etc"), so don't spend time running builds unless explicitly asked. Confidence: 0.7
- **Prefers direct action over plan/read-only mode.** When a task is already agreed, just make the edits ("do it now in edit mode") rather than pausing to describe what would be changed. Confidence: 0.6
- **Preserves UI/UX when fixing errors.** When asked to fix dev/build errors, solve the underlying problem without changing the visible UI or UX — user-facing behavior must stay identical while the issue is resolved. Confidence: 0.7
- **Renders inline HTML stored in JSON via `dangerouslySetInnerHTML`.** JSON data fields contain HTML (notably `<a>` anchor tags for internal links); these must be rendered with `dangerouslySetInnerHTML` so they appear as real links — never as literal escaped text. Confidence: 0.8
- **JSON data files are the authoritative content source for page sections.** When a component shows stale or wrong-brand copy (e.g., "Jaguar" text on a Mercedes site), rewrite the component to render its JSON data file rather than leaving hardcoded content in the component. Confidence: 0.7
- **Windows/PowerShell environment.** The project runs on Windows (`E:\` paths); shell commands should use PowerShell idioms (e.g., `Select-Object -Last N` instead of `head`). Confidence: 0.5
